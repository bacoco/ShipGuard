# ShipGuard 2.11.0 — Optional dialogue hooks

Implements the optional input/end-of-turn checks from #77, with separately opt-in pre/post-tool
adapters. Default behavior is unchanged: no new mandatory interview, model call, goal file or gate.
GrillGoal and mission-lock remain independent; raw tool results and arguments remain intact.

An optional explicitly configured controller returns bounded source-grounded findings, unknown or
unavailable. Its status is not an authorization or completion. Stop can request one correction,
without new user agreement; recursion, failures, timeouts and explicit deadlines are bounded.
The provided model controller requires a complete endpoint and model name, with no default provider,
model discovery or fallback. The hook collects no transcript and persists no state.

Activation, controller format, source selection, redaction and actual engine coverage:
[dialogue-hooks.md](../../plugins/shipguard/docs/dialogue-hooks.md).

Verification uses deterministic protocol/fault fixtures, native plugin/package validation and
installed-script checks. No model evaluation or live-model replay was run. The maintainer explicitly
cancelled that acceptance item; no behavioral guarantee, cost saving or comparative gain is claimed.
Trust/settings may prevent execution in a particular host session; installed does not mean active.

The 2.10.0 pre-review/dashboard remains included and its result contracts remain stable.
Update both Codex and Claude Code through their plugin managers, then start a new session.
