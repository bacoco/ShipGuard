## 2. Frictions et risques observés

1. **CI inexistante en pratique.** Actions désactivé, 0 exécution ; les workflows sont du code mort. Preuve : `gh api repos/bacoco/ShipGuard/actions/permissions`, `gh run list` vide. Tout repose sur la machine de Loic et le jugement de l'agent.
2. **Fusions sans relecture formelle.** PR #138 : 36 fichiers, +1496/−161, « 44 constats » corrigés, 0 review GitHub, fusionnée le jour même. Risque de régression silencieuse.
3. **Liste de tests périmée et dispersée.** 11 tests absents de `CLAUDE.md` ; un agent qui suit la consigne à la lettre saute un tiers des tests (dont tout le CLI et l'enregistreur).
4. **Publication manuelle en 5 fichiers + tag + release.** Risque de divergence (le README empile déjà « Version 2.18.0 » puis « Consolidated release 2.16.0 »).
5. **Documents contradictoires.** 17 vs 19 skills ; structure de `CLAUDE.md` incomplète ; specs d'avril sans statut.
6. **Reste de chantier.** `issue-101-integration-source.yml` et `.github/issue-101-baseline-check.txt` visent une branche `agent/101-...` qui n'existe plus sur `origin`.
7. **Hygiène des branches et copies de travail.** 17 branches fusionnées sur `origin` ; en local, 34 branches (33 déjà fusionnées) et autant de copies de travail `git worktree` conservées ; le `main` local est 51 commits derrière `origin/main`. Risque de travailler sur une base périmée.
8. **Pollution de la copie de travail par un test** + absence de `.gitignore` : un `git add -A` distrait commettrait des captures.
9. **Deux README à maintenir** : 593 lignes différentes, personne ne peut dire lequel fait foi.
10. **Tags v3.0.0 trompeurs** pour quiconque trie les tags par version.
